# ScriptFlow 生成上下文开关与执行边界需求

> **对于智能体：** 后续实现此需求时，必须先补测试再改代码。本文是 2026-07-30/2026-07-31 资产学习方案的边界修订：学习沉淀可以持续写入，但生成阶段是否读取沉淀必须由显式开关控制；执行器不能主动读取沉淀资产。

**目标：** 把“学习沉淀”和“使用沉淀”拆成两个独立能力。系统可以从成功试运行中持续沉淀资产，但默认生成必须严格按用户描述生成；只有用户显式打开增强开关时，AI 生成才允许参考历史资产和历史脚本。执行阶段始终只按 ScriptFlow 脚本和当前设备实时状态执行，不读取资产库、不使用历史脚本、不做隐藏自愈。

**背景：** 当前生成链路容易在用户没有明确页面前置或页面目标时，基于历史资产、历史脚本或页面目录过度补充 `onPage`、`expectPage` 等约束。例如用户只说“点击某个目标”，AI 可能推断出“从班级列表页进入班级详情页”。这会让脚本不再严格表达用户描述，也会让同一段自然语言在不同资产库状态下生成不同结果。

---

## 一、核心产品决策

### 1. 学习沉淀与使用沉淀必须解耦

学习沉淀是写入行为，只把已验证运行中的页面、交互、导航和用例候选写入资产库或候选库。

使用沉淀是读取行为，只在用户显式打开“使用历史资产和脚本增强生成”时，生成阶段才可以读取资产库、历史脚本和已验证导航。

关闭增强开关时，沉淀出来的任何内容都不能影响生成结果。

### 2. 执行器不依赖沉淀资产

执行器的职责是解释和执行脚本。它可以使用当前设备的实时能力，但不能主动读取历史资产或历史脚本。

执行器允许使用：

- ScriptFlow 中显式写出的 `text`、`icon`、`control`、`area`、`ordinal`、`position`、`search`、`onPage`、`expectPage` 等字段。
- 当前设备实时 UI hierarchy。
- 当前截图、OCR、通用视觉图标识别。
- 平台 driver 能力，例如点击、输入、滑动、前后台状态。
- 脚本中显式写出的 locator 或结构语义。

执行器禁止使用：

- PageAsset / InteractionAsset / NavigationEntry 数据库。
- 历史执行记录。
- 历史 ScriptFlow。
- 历史沉淀的 resourceId、页面跳转、控件路径。
- 失败后自动用历史资产“自愈并继续执行”。

执行失败后，系统可以生成修复建议或提示用户补充脚本，但不能在用户无感知的情况下套用资产继续执行。

### 3. ScriptFlow 是唯一执行事实来源

如果生成阶段启用了资产增强，资产只能帮助 AI 生成或修正标准 ScriptFlow 内容。最终执行时，行为必须已经物化为用户可见、可编辑、可保存的脚本语义。

不允许在执行计划里隐藏冻结资产 ID、资产版本、历史 locator bundle 作为执行器私有输入。

允许的形式：

```yaml
tap:
  target:
    icon: "emoji"
    area: "content"
    ordinal: 1
```

不允许的形式：

```yaml
tap:
  target:
    assetId: "interaction_asset_xxx"
    version: 3
```

也不允许生成标准脚本后，在 runner 内部再用资产库替换目标。

## 二、生成上下文策略

### 1. 严格按描述生成

默认模式。

输入来源：

- 用户自然语言描述。
- ScriptFlow schema 和抽象生成规则。
- 用户显式填写的 App ID、参数、平台。
- 用户显式开启“结合当前屏幕生成”时的受控 ScreenUnderstandingContext。

禁止输入来源：

- 历史脚本。
- PageAsset / InteractionAsset / NavigationEntry。
- 历史执行报告。
- 资产库推断出的页面前置、页面后置或导航路径。

生成规则：

- 用户没说页面，就不生成 `onPage` / `expectPage`。
- 用户没说从 A 到 B，就不补 A 页面前置或 B 页面结果。
- 用户只说“点击 X”，就只生成点击 X 的动作。
- 必要条件不足时返回 `needs_clarification`，要求用户补充。
- 可以参数化用户明确写出的动态值，例如会话名、班级名、输入文本。
- 不能把“历史上类似测试这样写过”作为生成依据。

示例：

用户输入：

```text
点击班级四十二号
```

严格模式下只允许生成：

```yaml
tap:
  target:
    text: "班级四十二号"
```

不能生成：

```yaml
onPage: "班级列表页"
tap:
  target:
    text: "班级四十二号"
expectPage: "班级详情页"
```

除非用户明确说“在班级列表页点击班级四十二号进入班级详情页”。

### 2. 使用历史资产和脚本增强生成

用户显式打开后才启用。

输入来源可以增加：

- 已验证历史 ScriptFlow。
- 已发布页面资产摘要。
- 已验证导航路径摘要。
- 已验证交互目标摘要。

增强规则：

- 资产只作为生成建议，不是执行隐藏输入。
- 只有用户描述中出现明确前置、目标、路径或领域对象时，才允许复用相关资产。
- 不能因为历史资产存在，就把用户没说的页面前置/后置强行加进脚本。
- 资产增强产生的内容必须带来源标记，供 UI 展示和用户审查。
- 增强生成失败时可以降级到严格模式或要求用户补充。

建议记录来源：

```ts
type GeneratedStepProvenance =
  | "user_explicit"
  | "screen_context"
  | "asset_suggested"
  | "history_script_suggested";
```

UI 应展示：

- 本次是否启用了历史资产/脚本增强。
- 引用了哪些资产类型和数量。
- 哪些步骤或页面约束来自用户明确描述，哪些来自资产建议。

### 3. 结合当前屏幕生成

这是独立开关，不等于资产增强。

开启后，生成阶段可以读取当前设备 Observation 和截图，并把受控 ScreenUnderstandingContext 交给 AI。看屏上下文只代表当前屏幕临时理解，不写入资产，也不允许执行器读取。

三个开关语义必须区分：

| 开关 | 作用阶段 | 是否读取设备 | 是否读取沉淀资产 | 是否影响执行器 |
| --- | --- | --- | --- | --- |
| 学习沉淀 | run 结束后 | 读取运行证据 | 写入候选/资产 | 否 |
| 使用历史资产和脚本增强生成 | 生成阶段 | 否 | 是 | 否 |
| 结合当前屏幕生成 | 生成阶段 | 是 | 否，除非同时打开增强 | 否 |

## 三、学习沉淀策略

### 1. 沉淀可以默认打开，但必须只写入

学习沉淀可以在质量门禁满足后持续写入候选或资产，例如：

- 页面身份候选。
- 交互目标候选。
- 导航候选。
- 可复用用例片段。
- 执行成功证据和失败诊断摘要。

但这些沉淀内容默认不参与下一次生成，更不能参与执行器定位。

### 2. 学习门禁

仍沿用已有质量要求：

- 只从已执行成功且结果已验证的 run 学习。
- 失败、崩溃、未验证、用户拒绝的 run 不能生成可启用资产。
- 候选必须脱敏，不能沉淀账号、班级实例、时间、数量等动态值。
- 不能沉淀固定坐标和一次性截图区域。
- 资产启用需要多次证据、冲突检测和必要人工确认。

### 3. 关闭增强时的隔离保证

当 `useAssetsForGeneration=false`：

- AI prompt 中不能出现资产摘要。
- AI prompt 中不能出现历史脚本片段。
- AI prompt 中不能出现页面目录、导航索引或交互资产。
- 生成结果不能因为资产库内容变化而变化。
- 缺少必要条件时必须返回澄清问题，而不是从资产库补。

## 四、API 与配置建议

### 1. 生成请求

建议在 AI 生成接口增加显式上下文策略：

```ts
type GenerationContextPolicy = {
  useAssetsForGeneration: boolean;
  useHistoryScriptsForGeneration: boolean;
  screenAssist: boolean;
};
```

也可以合并为模式：

```ts
type GenerationMode = "strict" | "asset_enhanced";
```

推荐前端文案：

- `严格按描述生成`
- `使用历史资产和脚本增强生成`
- `结合当前屏幕生成`

默认值：

```ts
{
  useAssetsForGeneration: false,
  useHistoryScriptsForGeneration: false,
  screenAssist: false
}
```

### 2. 生成结果 sourceSnapshot

每次生成或试运行都应记录：

```ts
generationContext: {
  mode: "strict" | "asset_enhanced";
  screenAssist: boolean;
  usedAssetIds: string[];
  usedHistoryFlowIds: string[];
  provenanceSummary: Record<string, number>;
}
```

严格模式下 `usedAssetIds` 和 `usedHistoryFlowIds` 必须为空。

### 3. 学习配置

学习沉淀配置与生成读取配置分离：

```ts
type LearningPolicy = {
  collectLearningEvidence: boolean;
  publishLearningAssets: boolean;
};
```

即使 `collectLearningEvidence=true`，也不能让生成阶段读取资产，除非生成请求显式开启 `useAssetsForGeneration`。

## 六、验收标准

- 默认生成不读取历史资产、历史脚本或导航索引。
- “点击 X”不会生成未明确的 `onPage` / `expectPage`。
- 打开增强开关后，生成可以参考历史资产，但所有引用可见、可审查、可关闭。
- 学习沉淀打开后，如果生成增强关闭，沉淀内容对生成结果没有任何影响。
- 执行器不读取资产库；删除或替换资产库不会改变同一份 ScriptFlow 的执行逻辑。
- 同一份 ScriptFlow 的执行结果只取决于脚本内容、参数、当前设备状态和执行器实时能力。
- 执行失败不会隐藏使用资产自愈；只给出可见诊断和修复建议。

## 七、开放问题

- 资产增强模式是否允许默认打开，还是必须用户每次显式勾选。当前建议默认关闭。
- 历史脚本增强是否和资产增强共用一个开关，还是拆成两个独立开关。当前建议先共用，sourceSnapshot 中分开记录。
- 学习沉淀是否提供 UI 开关。当前建议先作为后台策略，重点保证“不使用时不影响”。
- 未来如需要“自愈重试”，必须作为单独、显式、可回放的运行模式设计，不能混入普通执行器。
