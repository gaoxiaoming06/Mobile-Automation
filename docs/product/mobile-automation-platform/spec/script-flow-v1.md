# ScriptFlow v1

## 事实来源

| 数据 | 唯一事实来源 |
| --- | --- |
| 页面身份 | PageAsset |
| 测试过程 | 用例定义（内部使用 ScriptFlow 表达） |
| 测试数据 | ScriptFlow 参数定义与运行参数 |
| 执行结果 | Run、StepResult、Artifact |
| 页面内定位经验 | InteractionAsset |
| 已验证页面导航入口 | NavigationEntry |
| 脚本验证资格 | FlowVerification（绑定 sourceHash） |

## 测试分类模型

ScriptFlow 用三个正交维度描述测试，禁止用一个含混字段同时表达组合关系和执行意图：

- `kind: case | scenario` 表示组合粒度。单一可独立成立的业务目标是 case，多个独立业务目标的编排是 scenario。
- `purpose: navigation | fixture | business | recovery` 表示流程主要目的，分别对应到达状态、环境准备、业务验证和异常恢复。
- 每个步骤用 `role: setup | navigation | business | assertion | cleanup | recovery` 标记该步骤在测试中的语义职责。

AI 必须显式输出三个维度；确定性校验器负责拒绝自相矛盾的组合，例如 navigation 流程包含表单输入、发布、删除或 business 步骤。旧文档在底层解析时可默认为 business，新 AI 草稿不允许缺省。

## 页面资产

页面资产按真实 App ID 和平台隔离。当前 ClassIn Android 使用 `cn.eeo.classin`。

页面资产可保存：

- 页面名称、稳定 key、平台范围和页面变体类型。
- OCR 文本、截图重点区域、视觉基线及其他页面身份 matcher。

页面资产不得保存元素定位器、坐标、业务动作、跳转目标、发布流程或页面任务。动作目标属于用例，系统内部将用例编译为 ScriptFlow，并由执行器在实时页面中通过 OCR、标准图标语义或通用控件语义定位。

页面资产不是创建测试的前置条件。零资产 App 可以根据完整的用户操作描述生成待试运行草稿；页面资产用于验证已知页面身份、提高结果判定能力，并在后续执行中参与页面状态识别。

## 交互资产

InteractionAsset 是试运行成功后形成的页面内定位经验，按 App、平台、所属页面、动作和语义契约隔离。它只保存 OCR 锚点、标准图标、控件结构或其他非坐标定位证据，不保存目标页面和业务流程。

ScriptFlow 不引用 InteractionAsset ID。预览时系统使用 `onPage + action + target` 严格查询唯一资产；命中后把资产内容和版本冻结进内部执行快照并计入 `planDigest`。没有命中时继续使用通用语义定位；同时命中多个资产时预览失败，必须先消除歧义。

## 导航入口

NavigationEntry 是试运行验证出的轻量页面跳转经验，保存 `fromPage + 语义动作 + toPage`，不保存坐标、截图区域或完整业务流程。它与 InteractionAsset 分离：InteractionAsset 回答“如何找到入口”，NavigationEntry 回答“这个入口验证后会到哪个页面”。

只有试运行整体通过、动作步骤通过和目标页面断言通过时才记录证据。相同 App、平台和语义路径再次成功时合并来源 Run、步骤和证据；至少 3 次独立成功运行和 2 份证据通过确定性准入后，后台才能启用 NavigationEntry。AI 规划与运行时只读取已启用条目。

## 用例中心

用例中心是用户维护可复用 fixture 和 business 流程的入口，例如登录、退出登录和创建课堂。纯 navigation 流程不进入用例中心，而是在验证成功后由系统内部导航索引复用。用户可以查看用例说明、参数、版本和可读执行步骤，也可以配置参数后运行用例，但不直接查看或编辑 ScriptFlow YAML。

修改已有用例必须进入 AI 用例工作台。系统将当前完整用例作为上下文，用户只描述希望调整的内容，AI 生成完整新版本；保存时校验原版本，避免覆盖并发修改。

### 目标页面导航

当用户只表达“进入、打开、前往或回到某页面”时，AI 必须将其理解为目标状态，而不是返回、重启或点击某个入口的操作指令：

```yaml
- id: reach-home
  reachPage:
    page: classin.teacher.classes
    policy: safe
```

`reachPage` 在规划阶段不读取设备页面。运行时先识别当前页面：已经位于目标页则不执行设备动作；否则只使用预览时冻结的导航索引寻找安全路径，并在每个导航片段后验证目标页面。没有可靠路径时执行失败，不得猜测返回次数或自动重启 App。

导航索引是系统派生数据，不由用户手工维护。它包含两类来源：已验证启用用例派生的多动作片段，以及用户接受的 NavigationEntry 单动作片段。一个片段可以穿过未录入的菜单、弹窗或临时页面，但起点和终点必须能由页面资产识别。包含提交、发布、删除、支付等危险动作的流程不得进入导航索引。

预览只读取当前 App 和平台的导航索引快照，不遍历或复制全部用例源码。索引摘要参与 `planDigest`，索引变化后必须重新预览。执行器识别当前页后对轻量索引做路径搜索，并顺序执行命中的多动作片段。

只有用户明确要求“点击返回”“重启 App”等过程时，AI 才生成相应的操作步骤。

步骤可声明 `onPage` 和 `expectPage`。执行器在运行时识别页面，并在已知目标页时只匹配指定页面，避免全库视觉扫描。

## 执行原则

1. 内部 ScriptFlow 先经过 schema 和参数校验，YAML 不作为面向普通用户的编辑界面。
2. `tap` 与 `selectText` 默认记录为交互风险；提交、发布、删除和支付使用更具体的风险类别，供报告审计但不要求运行前逐项确认。脚本禁止显式填写 `risk: none`。
3. 动作目标必须且只能使用 `text`、`semantic`、`icon` 或 `control`。`text` 表示用户明确提供或目录中已有的屏幕原文；不知道准确标签时使用 `semantic` 描述操作意图，由执行器从实时 OCR 候选中选择唯一高置信结果；`icon` 表示带区域和位置约束的标准图标，`control` 表示由执行器实时识别的通用控件。脚本不能引用页面元素资产 ID。
4. `tap.search` 声明点击动作是否允许查找：`visibleOnly` 只检查当前屏幕，`auto` 先检查当前屏幕、必要时回到顶部再逐屏扫描，`scroll` 按指定方向扫描。查找算法属于执行器，脚本不展开成机械滑动步骤。v1 的输入、清空和选择动作不接受 `search`。
5. v1 的标准顶栏图标、内容区标准新增按钮和复选框不要求录制元素资产。底栏和业务入口存在可见文字时优先使用 `text`；尚未支持的自定义图形必须在生成阶段报告能力不足，不得退化为元素 ID、坐标或圈选区域。
6. 坐标和录制区域不能成为目标身份，也不能作为点击回退。
7. 已录入的目标页面由 PageStateService 验证。目标页面未录入但用户提供了完整操作链时，可以生成 `trial_ready` 草稿；如果有稳定结果文字则使用 `assertText`，否则试运行完成后必须由用户确认业务结果。只有目标动作本身存在歧义、无法表达或缺少必要参数时才拒绝生成。
8. 运行前必须预览。预览固定父流程版本、全部 `runFlow` 依赖版本、参数和编译计划，并返回 `planDigest`；执行只接受同一摘要。
9. 敏感参数只在内存中参与执行，持久化步骤按参数来源脱敏，不扫描或改写无关结构字段。
10. 一个 ScriptFlow 产生一个 Run，报告按脚本步骤展示。

## AI 生成

新建用例时，AI 输入包含自然语言、目标 App、平台、页面身份目录和可复用用例摘要，不包含页面元素或其定位信息。修改用例时额外包含当前完整用例，未被用户提及的步骤、参数和约束应保持不变。AI 输出必须是可校验的 ScriptFlow v1 文档，不直接控制设备，也不能生成 schema 之外的目标字段。

AI 草稿生成后可以直接临时执行，也可以保存到用例中心。临时执行复用正式用例的校验、预览摘要、风险审计和执行器，但不写入用例中心。

每次临时执行写入独立的“最近测试”历史，保存用户描述、精确 ScriptFlow 快照、非敏感运行参数和最近 Run 引用。它不是用例中心，也不复制报告、视频或截图附件。同一 App、平台和脚本内容的重复执行合并计数；密码等 sensitive 参数永不写入历史，再次执行前必须由用户补充。

AI 草稿有三种生成状态：

- `ready`：结构可执行，当前 sourceHash 已通过结果验证，可以直接执行。
- `trial_ready`：结构可执行但当前版本尚未验证，只能保存草稿或真实试运行。
- `needs_clarification`：动作或必要参数存在歧义，需要用户补充后才能预览。

确定性验证服务负责把模型结果映射为 `verified / needs_trial / blocked`，模型不能自行声明脚本已验证。普通运行只接受 `verified`；试运行默认关闭视频并拒绝无限循环。试运行的设备动作通过并不自动代表业务结果通过：有自动页面或文字断言时可以直接验证，没有自动结果判定时必须由用户确认。

试运行成功且结果已验证后，系统从实际成功执行的步骤生成不可执行的交互证据；如果步骤还具备已知起始页、已知目标页和通过的页面断言，则同时生成导航证据。后台按 App ID、平台、候选种类和稳定语义聚合，至少达到 3 次独立成功运行和 2 份证据后才进入晋级。精确文字交互与确定性导航不调用 AI；页面身份、图标和其他高歧义候选异步调用 AI 提议稳定语义，再由确定性规则检查样本一致性、敏感信息、页面冲突和非坐标约束后发布。失败执行、用户否认结果和未确认结果不得贡献证据。已验证脚本修改后 sourceHash 改变，必须重新试运行。

普通执行不调用资产学习 AI。后台轮询只处理新达到门槛的候选，没有候选时不产生模型请求；AI 分析失败不会影响设备执行和报告生成。自动页面身份不能把可滚动、可折叠或屏幕外的操作入口当作必要 matcher，稳定文字必须在多份样本中同时存在。

当前生产模式由服务端源码常量 `ASSET_LEARNING_MODE` 固定为 `disabled`：运行结束不创建学习会话或候选，后台不扫描、分析或发布资产。该模式不提供用户设置、API 或环境变量覆盖；第一阶段生成与执行验收完成后，才通过代码评审进入 `shadow`，影子质量达标后再进入 `active`。已有 active 资产在所有模式下仍可作为只读增强能力使用。

已启用 InteractionAsset 记录独立健康度。成功使用会清零连续定位失败；只有明确的目标未找到错误才累计，连续 3 个运行失败后状态变为 `degraded` 并从后续预览中排除，同时在失败报告中提示该操作需要重新学习。ANR、网络错误、业务断言失败和用户停止不降低资产健康度。

AI 输出必须经过与人工导入完全相同的 ScriptFlow schema 校验。任何旧字段、未知字段、元素资产引用、坐标或区域目标都直接判为无效，不做兼容转换，也不写入数据库。系统可以把完整校验错误反馈给模型修复一次；第二次仍不合法时终止生成并向用户显示简短错误，不能使用上一稿或部分步骤继续执行。

网页端 AI 配置只允许启用本机 Codex Provider、选择模型和超时。外部 HTTP Provider 只能由运维通过环境变量配置，地址和密钥不写入项目数据库。

## 验收

- 页面资产库不出现连接边、PageTask、MetaFunction、元素定位器或动作资产。
- 自然语言可以生成可读、可直接执行或保存的用例草稿，不向用户暴露 YAML。
- 零资产 App 的完整操作描述可以生成待试运行草稿，不强制用户先进入资产录制。
- 未验证脚本不能普通执行、启用保存或进入导航索引；试运行失败不能学习资产。
- 多次试运行验证的页面内定位经验可由后台沉淀并在后续预览中冻结复用，脚本中仍不出现资产 ID、坐标或区域。
- 多次试运行验证的页面跳转可由后台沉淀为 NavigationEntry，并同时供 AI 规划和运行时 `reachPage` 使用。
- 普通用户界面不要求审核资产候选；只有测试结果缺少自动判定时才要求确认结果。
- 资产按 App ID 和平台隔离，过期交互资产连续 3 次明确定位失败后自动停止复用。
- 用例可保存、版本化、参数化并运行，并可通过自然语言生成新版本。
- `onPage` / `expectPage` 使用统一页面身份服务。
- REST、CLI 和 MCP 只暴露页面资产、ScriptFlow、Run 和报告能力。
- REST、CLI 和 MCP 均使用 `preview -> planDigest -> run` 契约；子流程变化后旧摘要立即失效。
- Android 先完整落地；iOS、Harmony 和 Flutter 复用视觉页面样本扩展字段，不引入平台专属定位为主路径。
