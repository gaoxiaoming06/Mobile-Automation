# 资产驱动测试产品形态需求

## 背景

PageStateFlow 当前已经具备页面资产录入、页面匹配、页面能力、连接边、资产驱动巡检、目标页面执行和 AI 诊断修复等能力，但产品形态仍然容易让使用者误解为“圈选坐标后回放”。后续平台需要从“录制一条流程”升级为“按 App 管理页面状态资产，并基于资产持续测试 App”。

本需求文档沉淀当前已确认的产品方向，作为后续实现“资产录入、参数管理、资产巡检、元功能、组合用例、AI/MCP 能力”的统一口径。

## 产品目标

平台最终目标是：对任意移动 App，录入可复用的页面状态资产后，系统可以稳定识别当前页面、理解页面能力、执行能力并验证结果，从而支持目标流程测试、资产巡检、全 App 周期巡检、性能和稳定性监控，以及 AI 辅助诊断和资产修复。

目标不是为 ClassIn 写一套专用脚本，也不是单纯重复录制好的坐标流程。ClassIn 只是当前验证样例，产品模型必须保持 App 无关。

## 核心原则

1. 资产是事实来源，不是脚本。
   页面资产描述“当前是什么页面、页面上有什么能力、能力执行后会发生什么”，而不是保存一串不可理解的点击坐标。

2. PageCapability / PageElement 是原子能力源头。
   “原子能力”就是资产录入页里的页面能力，例如点击搜索、输入手机号、选择指定班级、进入发布活动页。它属于页面资产库，不属于目标页面测试。目标页面测试、元功能和组合用例只能引用这些能力，不能重新定义一套能力。

3. PageTransition 由页面能力派生或引用。
   连接边应该表达某个页面能力执行后的结果，例如跳转到目标页、打开弹层、页面状态变化。连接边不应成为第二套可编辑动作源。删除或废弃页面能力时，相关边必须同步删除、废弃或标记为不可执行。

4. 执行必须先重定位，再操作。
   运行时不能直接点击录入时的固定坐标。系统必须通过 OCR、视觉模板、结构约束、顶部图标、列表项定位等策略在当前截图上重新找到目标；找不到时失败并进入报告、修复 UI 或 AI 修复流程。

5. 运行参数由参数集统一管理。
   手机号、账号、班级名、课堂名、开关状态等运行参数不应散落在某个执行页面里临时填写。平台应维护按 App / 环境 / 账号状态组织的 Parameter Profile，执行巡检、目标流程和组合用例时选择一套参数集。

6. AI 可以修资产，但必须遵守系统规则。
   AI 在异常时可以读取证据、判断原因、生成资产修复 patch，并在高置信、低风险、系统校验通过后自动应用和重试。AI 不应绕过资产规则直接写库；规则无法表达的问题要反向记录为平台规则缺口。

7. 所有能力都应可通过 MCP 暴露。
   用户能在面板上做的关键动作，例如查询资产、发起执行、选择参数集、验证页面、提交资产 patch、查看报告，后续都应能通过 MCP 提供给 AI Agent。

## 核心概念模型

| 概念 | 定义 | 说明 |
|---|---|---|
| App Workspace | 一个被测 App 的资产工作区 | 按 package / bundle、平台、版本范围管理资产 |
| PageModel | 一个稳定页面或页面变体 | 例如主页、登录页、班级详情、发布活动类型选择页 |
| PageMatcher | 页面识别规则 | 组合 OCR、截图重点区域、语义区域、视觉锚点等 |
| PageCapability / PageElement | 页面原子能力 | 例如点击搜索、选择班级卡片、输入密码、勾选协议 |
| PageTransition | 能力执行结果 | 例如主页点击搜索后到搜索页 |
| PageTask | 页面内多步任务 | 例如登录页内完成账号密码登录、新建课堂页填写表单 |
| Parameter Profile | 运行参数集 | 一组账号、班级、课堂、开关等业务数据 |
| Meta Function | 元功能 | 由多个页面能力 / PageTask 编排出的可复用业务能力 |
| Test Case | 组合用例 | 由多个元功能或页面路径组合成完整测试场景 |
| Patrol Plan | 巡检计划 | 按页面资产自动生成的周期性验证计划 |
| AI Repair Patch | AI 资产修复补丁 | AI 基于证据生成、系统验证后应用的资产修改 |

## 需求列表

### REQ-ADT-001：App 级资产工作区

平台必须支持按 App 管理资产。每个 App 工作区至少包含 PageModel、PageMatcher、PageCapability、PageTransition、PageTask、Parameter Profile、执行记录和报告。

验收要点：

- 支持同一平台录入多个 App 的资产。
- 支持同一逻辑 App 管理 Android / iOS 双端资产。
- 不允许 ClassIn 专用逻辑污染通用资产模型。

### REQ-ADT-002：基于规则的资产录入

平台必须继续强化资产录入流程。录入时用户不是“随便圈一个区域”，而是在定位策略工作台中选择定位策略、填写语义参数、预览当前截图是否可定位，并保存为可验证资产。

最低应支持的定位策略：

- OCR 文本定位。
- 视觉模板 / 截图区域重定位。
- 顶部栏图标定位。
- 列表 / 网格项定位。
- 结构相对定位。
- 锚点文字 + 相对偏移定位。

验收要点：

- 每个策略都有独立表单，不再用同一套圈选表单表达所有能力。
- 保存前可做当前截图定位预览。
- 质量校验能说明通过、建议复核或失败的原因。

### REQ-ADT-003：页面能力和连接边一致性

平台必须把 PageCapability / PageElement 作为连接边的源头。连接边页面只展示由页面能力派生或引用的边，不作为独立动作编辑入口。

验收要点：

- 新建跳转型页面能力时，可同时生成对应 PageTransition。
- 删除或废弃页面能力时，相关 PageTransition 同步废弃或标记不可执行。
- 连接边列表能说明来源能力、目标页、验证规则和当前可执行状态。
- 不允许同一个动作在 PageElement 和 PageTransition 中各保存一份互相独立的定义。

### REQ-ADT-004：参数中心与参数集

平台必须提供参数中心，用于维护 App 级 Parameter Profile。一个参数集代表一种可执行上下文，例如某个账号、该账号拥有的班级、课堂名模板、权限状态、业务开关。

验收要点：

- 支持创建、编辑、复制、删除参数集。
- 参数值支持普通字符串、布尔值、数字和模板值。
- 参数项能显示被哪些页面能力、PageTask、元功能或用例引用。
- 执行资产巡检、目标流程和组合用例时可以选择参数集。
- 缺少必需参数时，执行前给出明确提示。

### REQ-ADT-005：资产驱动巡检

平台必须支持基于页面资产执行巡检。巡检不是盲目探索，而是先匹配当前页，再按该页已录入资产验证页面健康、元素定位、连接边可达性、PageTask 可执行性、性能和异常。

验收要点：

- 支持当前页巡检。
- 支持从当前页开始按资产图扩展巡检。
- 支持全 App 周期巡检的规划入口。
- 巡检时只执行正式资产，不把未确认 OCR / UI 候选当作动作。
- 巡检过程能实时展示批次状态、当前边、剩余项、失败项和停止按钮。

### REQ-ADT-006：元功能库

平台必须支持把一段资产驱动流程保存为元功能。元功能由页面能力、PageTransition、PageTask 和参数引用组成，用于表达可复用业务能力。

示例：

- 登录账号。
- 进入指定班级详情。
- 创建课堂但不发布。
- 发布作业。
- 从班级详情进入学习方案。

验收要点：

- 元功能可以从当前规划路径保存。
- 元功能可以手工编排已有页面能力和 PageTask。
- 元功能保存时校验路径可达、参数齐全、目标页可验证。
- 元功能执行报告显示每个原子能力的实际结果。

### REQ-ADT-007：组合用例

平台必须支持把多个元功能组合成完整测试用例。组合用例用于表达端到端业务测试，而不是重复录制每个点击。

示例：

```text
切换账号 -> 进入指定班级 -> 创建课堂 -> 进入课堂 -> 验证课堂状态
```

验收要点：

- 用例可以引用多个元功能。
- 用例可以选择参数集。
- 支持单次、N 次、循环和定时执行策略。
- 用例报告能展示元功能级、原子能力级和页面级结果。

### REQ-ADT-008：临时执行与保存执行计划

平台需要保留临时执行能力。用户可以临时配置一条路径或目标动作立即执行，也可以选择保存为元功能或组合用例。

验收要点：

- 临时执行不会污染资产库。
- 临时执行成功后可以一键保存为元功能草稿。
- 临时执行失败时可以进入资产修复或规则缺口记录。

### REQ-ADT-009：AI/MCP 诊断与修复

平台必须把 AI 诊断和修复建模成受控能力。AI 只在异常或用户主动请求时介入，不参与普通步骤规划；但当 AI 高置信判断为资产问题且能按规则生成 patch 时，可以自动修复并重试。

验收要点：

- 失败证据包包含截图、OCR、页面匹配详情、定位详情、执行日志、性能和异常事件。
- AI 输出结构化分类：App 问题、资产问题、自动化系统问题、环境问题、未知。
- AI patch 必须经过 schema 校验、资产规则校验、dry-run 定位校验和风险校验。
- 校验通过且策略允许时，系统自动应用 patch 并重试失败边。
- 校验失败时，报告应说明是 AI patch 不合规、规则缺口还是证据不足。
- MCP 应暴露查询资产、查询报告、提交 patch、验证 patch、应用 patch、回滚 patch、重试执行等能力。

### REQ-ADT-010：执行报告与资产健康

平台必须把测试结果、资产健康和修复建议统一呈现。

验收要点：

- 报告展示页面匹配、元素定位、边执行、目标页验证和性能采样。
- 资产健康面板展示页面匹配通过率、元素定位通过率、连接边通过率、PageTask 通过率和最近失败。
- 报告中可直接跳转到对应资产编辑 / 修复入口。
- AI 修复必须记录修复前后 diff、验证结果和是否自动应用。

## 推荐产品信息架构

| 模块 | 主要职责 |
|---|---|
| App 工作区 | 管理 App、平台、版本范围和资产包 |
| 页面资产 | 管理 PageModel、页面匹配、页面能力、连接边、PageTask |
| 定位策略工作台 | 录入和预览 OCR / 视觉 / 结构 / 列表等定位策略 |
| 参数中心 | 管理 Parameter Profile 和参数引用 |
| 元功能库 | 保存可复用业务能力 |
| 用例编排 | 组合多个元功能形成测试用例 |
| 资产巡检 | 当前页、周边页面、全 App 的资产驱动巡检 |
| 执行记录 | 展示批次、用例、元功能、边和步骤级报告 |
| AI 诊断 | 查看异常归因、资产 patch、验证和应用记录 |

## 分阶段路线

### P0：模型一致性收口

- PageCapability 作为原子能力源头。
- PageTransition 由能力派生或引用。
- 清理孤儿边、废弃边和无来源边。
- 删除明显废数据，例如只靠 candidateIndex / 固定格子序号的列表点击资产。

### P1：定位策略工作台

- 把录入 UI 从“圈选区域”改成“选择定位策略 + 填语义参数 + 预览定位”。
- 覆盖 OCR 文本、视觉模板、顶部图标、列表项四类高频策略。
- 质量校验和执行报告使用同一套规则。

### P2：参数中心

- 建立 App 级 Parameter Profile。
- 资产巡检、目标执行、元功能和组合用例统一选择参数集。
- 参数引用关系可追踪。

### P3：元功能与组合用例

- 支持从执行路径保存元功能。
- 支持手工编排元功能。
- 支持组合用例单次、N 次和循环执行。

### P4：全 App 资产巡检

- 从当前页巡检扩展为页面图循环巡检。
- 支持恢复策略、风险策略、覆盖统计、停止本轮和继续下一轮。

### P5：AI/MCP 能力开放

- 把面板能力沉淀为 MCP 工具。
- AI 可查询资产、诊断失败、提交修复、验证修复、继续执行。
- 规则缺口自动沉淀到需求和资产规则文档。

## 非目标

- 不把当前系统做成 ClassIn 专用测试脚本集合。
- 不要求 AI 参与每一步正常规划和点击。
- 不恢复固定坐标作为默认执行策略。
- 不把 UIAutomator / WDA 树作为正式页面身份的主依据。
- 不把未确认的自动探索候选直接写入 active 资产。

## 开放问题

| ID | 问题 | 影响 |
|---|---|---|
| Q-ADT-001 | Parameter Profile 是否需要区分测试环境、账号权限、数据生命周期和清理策略？ | 影响参数中心数据模型 |
| Q-ADT-002 | 元功能是否需要版本管理和审批状态？ | 影响元功能库治理 |
| Q-ADT-003 | AI 自动应用资产 patch 的默认风险阈值是多少？ | 影响自动修复安全策略 |
| Q-ADT-004 | 全 App 巡检的停止条件和恢复策略如何配置？ | 影响长时间巡检稳定性 |
| Q-ADT-005 | 跨 Android / iOS 的同一逻辑页面资产如何复用和差异化展示？ | 影响 App 工作区和资产包设计 |
